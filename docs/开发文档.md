# 酒馆助手功能文档

适用版本：0.2.2。日期：2026-10-18。

## 1. 程序做什么

通过 Windows 桌面界面，识别战网和炉石的画面，在经过确认的游戏状态下发送鼠标、拖动或 Esc 操作。识别和记录在本机完成。程序不是胜率优化工具，不保证名次或分数。

## 2. 功能一览

| 功能 | 当前行为 |
| --- | --- |
| 桌面界面 | 运行概览、界面校准、运行设置三个页面 |
| 运行控制 | 启动、暂停、继续、停止；F8 暂停、F9 停止 |
| 战网路径检测 | 已保存的有效路径 → 运行中客户端 → 注册表 → 常见目录 |
| 战网启动 | 已运行时使用现有窗口；未运行时从检测路径启动 |
| 游戏导航 | 游戏入口、公告、主菜单、战棋大厅、匹配 |
| 英雄选择 | 识别中间两个候选的可选状态，按偏好选择并确认 |
| 基础操作 | 购买正向识别的随从、出牌、升本、处理已支持的选择界面 |
| 满场处理 | 可选卖出最左随从腾位，每回合最多一次 |
| 法术处理 | 读取明确类型后处理已支持的法术；未知效果跳过 |
| 结算循环 | 记录可靠读到的名次、总分、分差，返回大厅并重新匹配 |
| 历史记录 | SQLite 保存，GUI 查看，导出 CSV |
| 校准 | 导入/采集图片，保存点位、区域、状态和标记模板 |
| 自动适配 | 读取目标显示器工作区、处理 DPI，必要时调整游戏窗口 |
| 前台恢复 | 可选等待键鼠空闲 2 秒后恢复目标前台；主动暂停不会自动解除 |

## 3. 自动适配如何工作

1. 找到真实游戏窗口，读取客户区和窗口边框的物理像素尺寸。
2. 读取该窗口所在显示器的完整区域与工作区，结合窗口样式与客户区边缘判断是否全屏。
3. 符合校准比例的全屏按完整显示器区域验证，保持原尺寸。普通窗口比例不匹配、客户区过小或超出工作区时，扣除任务栏、边框和留白，计算可容纳的最大窗口并居中。
4. 调整后重新读取实际客户区。窗口不接受目标尺寸时暂停，不沿用旧坐标。
5. 清除旧画面对应的操作，重新观察并等待状态稳定。
6. 模板按图像尺寸换算；较小分辨率对模板增加一像素尺寸误差的匹配候选，不降低原匹配阈值。场面识别使用已有的标准画布换算，实际输入仍落在真实客户区。

只观察模式不移动或调整游戏窗口。关闭自动适配后恢复原来的比例检查。适配不改变显示器分辨率，不强制切换独占全屏；全屏比例不符合校准时需要先手动改为窗口模式。

## 4. 战网自动检测如何工作

只接受实际存在的 `Battle.net.exe` 或 `Battle.net Launcher.exe`。路径可为空，也可以是从其他电脑复制来的失效路径。

按顺序检查已保存路径、可见的战网进程路径、当前用户和本机注册表的 32/64 位安装记录、Program Files 等常见安装目录。读取注册表里的安装目录或图标路径，不执行卸载命令。没有找到时显示提示，允许手动选择。

战网响应式布局发生变化时，已校准 PC 布局还可以结合明确的游戏名和左下角唯一“进入游戏”文字定位按钮。只有按钮文字而没有游戏名，或画面显示“更新”，不会据此确认可启动状态。

## 5. 对局流程

战网 → 游戏入口 → 主菜单 → 战棋大厅 → 匹配 → 选英雄 → 招募/战斗交替 → 结算 → 返回大厅 → 下一局。

公告、断线、Esc 菜单、认输确认、局内选择等使用独立状态处理。识别失败、窗口被遮挡、旧画面过期或流程超时，会等待或暂停并写入日志。手动暂停后继续时重新识别。

连续手牌处理以“稳定确认手牌减少且目标选择结束”为进度点：此后重置读牌尝试额度并刷新坐标。无进展时最多三次读取，保留每回合总动作上限。需要先选择效果的指向性法术会等待后续目标选择，不能提前开始下一张。

## 6. 数据含义

- `normal`：正常结束。
- `test_concede`：测试中主动认输。
- `interrupted`：程序停止时对局未完成。
- 名次、分数读取失败时保留空值，不编造数据。
- 分差优先由可靠的对局前后总分计算；界面不能可靠读到的字段继续保留未知。
- “截图补读完整”表示后续回放补齐过结果，不等同于原始运行一次全部读取成功。

## 7. 验证范围

0.2.0 已在本机通过 140 项测试，包括多显示器坐标规划、路径发现优先级、20 组跨尺寸真实图片状态回放，以及原有功能回归。本机 125% DPI 的实际自有窗口调整和实际战网运行路径、注册表检测已通过。打包验证另见发布说明。

0.2.1 本机共 146 项测试通过，新增全屏与任务栏区域回归，覆盖不同任务栏位置、负坐标、1440p 和 4K 几何。打包程序在本机 1920×1080、125% DPI 下保持全屏不变；真实炉石运行日志也确认 `mode=fullscreen`、`changed=false`，并已观察到该局结算和返回大厅记录。公共 CI 不包含私人截图，相应用例会跳过。这些结果不替代跨电脑完整对局验收。

0.2.2 本机共 153 项测试通过，新增同回合连续施法、目标等待和失败额度测试。打包自检用实际封装的决策引擎模拟直接拖动与额外目标确认两种情况，各连续使用五张法术；没有模拟真实游戏效果。7/7 金币 OCR 误识别仍是已知问题。

此前基础买牌、打牌、升到 5/6 级、饰品确认、结算和部分法术有本机实测记录。自动卖出后继续打牌和购买有实机证据；“联盟旗帜”打出、抉择、指向有效果证据，测试牌由用户买入。

尚未完成跨电脑完整对局、多显示器实际拖动、所有显示缩放组合和所有法术的验收。附魔链索的识别与处理已实现，新一轮实际施放仍待验证。英雄技能、精细刷新策略和阵容强度判断尚未完整实现。

## 8. 开发结构

`gui.py` 管理界面；`runner.py` 运行循环；`vision.py` 与 `pc_layout.py` 识别画面；`engine.py` 决定操作；`windows.py` 执行窗口和输入操作；`adaptation.py` 规划窗口尺寸；`discovery.py` 检测安装路径；`store.py` 保存记录。

Windows DPI 行为参考 [Microsoft SetThreadDpiAwarenessContext](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddpiawarenesscontext)，当前工作线程使用每显示器 DPI 感知，关闭后恢复线程原上下文。
